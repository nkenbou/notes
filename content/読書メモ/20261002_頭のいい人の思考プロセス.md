## 読書メモ

### TOC 思考プロセスの原理とツール

思考プロセスの「基本的な質問」「ツール」「原理」の対応。

| 基本的な質問         | ツール       | 原理   |
| -------------- | --------- | ---- |
| 何を変えるのか？       | 現状問題構造ツリー | 十分原因 |
| 〃              | 雲         | 必要条件 |
| 何に変えるのか？       | 〃         | 〃    |
| 〃              | 未来問題構造ツリー | 十分原因 |
| 〃              | 前提条件ツリー   | 必要条件 |
| どのように変化を起こすのか？ | 〃         | 〃    |
| 〃              | 移行ツリー     | 十分原因 |

十分原因と十分原因をつなげるところに必要条件が挟まっている。
厳密に検証が必要な仮説を立てるときは「十分原因」を使う。
目標達成のための行動 (解決策) を決めるときには「必要条件」を使う。

思考プロセスのツール間のつながりと使用順序。

1. 現状問題構造ツリー
	- UDE (好ましくない結果) を洗い出す
	- ツリーを作成し、UDE と問題の関係を把握する
	- コアの問題を見つける
2. 雲
	- コアの問題に関するコンフリクトを解消する「代替策」 (方針) を考える
	- 相手と目的を共有する
	- 最初の「目標」を選択する
3. 未来問題構造ツリー
	- 方針の「代替策」を一番下、最初の「目標」を一番上に設定する
	- 現状問題構造ツリーのそれぞれの問題に解決策 (代替策) を注入して問題を解消する
	- すべての問題を解消することで「目標」を達成できることをシミュレートする
4. 前提条件ツリー
	- 中間目標を定める
	- 中間目標を達成するための必要条件を考える
	- 必要条件の適切な代替策を探し、選択する
5. 移行ツリー
	- 現状に対し起こす行動 (インジェクション) を決める
	- インジェクションの「結果」が次のステップの現状 (状態) になる
	- それを繰り返して目標にたどり着くまでを予測する

### 制約の種類と関係

制約には、物理的制約、方針の制約、パラダイムの制約がある。
方針やパラダイム (物事の見方や価値観、常識) が物理的制約を決める。
パラダイムが方針の制約を決める。
制約は、パラダイムの制約 → 方針の制約 → 物理的制約 に影響を与える。

### システムの成功を測る尺度

会社というシステムを考えた時の一般的な尺度:

- スループット
- インベントリ
- 業務費用

ソフトウェア開発というシステムに当てはめると...

- スループット => スループット (例. ベロシティ、一定期間のスパンでリリースする価値の量と大きさ)
- インベントリ => 前工程の成果物、学習コスト
- 業務費用 => メンバーの給料くらい？それほど種類はなさそう

それ以外の尺度が適切な可能性もある。
例えば、Four Keys (DORAメトリクス) など。

改善努力を始めるには、尺度について**オープンに話し合う**ところから始めるべきである。

### 論理ツリーの図の要素の解説

- エントリーポイント: 矢印が入ってこないエンティティ
	- 現状のシステムの中に存在するエンティティ (表現方法の例. 角が丸い四角形)
	- まだ存在しないエンティティ (表現方法の例. 角が四角い四角形)
		- = **インジェクション**

### 十分原因

十分原因は、結果—原因—結果の思考パターンのこと。
これを図示したものが、論理ツリーとも呼ばれる図の一種となる。

思考プロセスでは、利用シーンに応じて十分原因を採用した次のツールを定義している。

- 現状問題構造ツリー
- 未来問題構造ツリー
- 移行ツリー

それ以外にも十分原因を自由に使って思考することができる。

**参考ページ:** 44

### 賛成留保

意見が合致する度合いが極めて低いか、または高いときには厳密に問い直す。

- 「集団思考」の危険を回避
- 誤った仮定の回避

賛成留保は十分原因の因果関係を検証するためのツール。

- レベル1の賛成留保
	- エンティティの存在に対する賛成留保
		- エンティティが本当に存在するかを疑う
	- 因果関係の存在に対する賛成留保
		- エンティティ同士をつなぐ因果関係を疑う
	- 明確性に対する賛成留保
		- エンティティが完結した文で表現されているかを確認する
		- 相手と意見が食い違う場合、まずは、自分が相手の言うことを十分理解していないと考える
		- 他人の仕事を検討するときには最初に使う
		- 自分が作図しているときは最後に使う
- レベル2の賛成留保 (「エンティティの存在」ないし「因果関係の存在」に答えが得られていないときに使う)
	- 追加的原因の賛成留保
		- 結果を生じる別の原因の存在を疑う
	- 不十分原因の賛成留保
		- 複数原因の組み合わせの存在を疑う
	- 予測される結果の賛成留保
		- その原因があれば存在するはずの別の結果の存在を疑う
		- 原因の存在、結果の存在を吟味する

実際に使いたくなったときには書籍を参照すること。

### 必要条件

- 矢印の根本のエンティティ: 必要条件
- 矢印の先のエンティティ: 目標
- 矢印: 仮定 (必要条件を目標に結びつける)

必要条件のエンティティは完全な文でなくてよい。

まずコアの仮定を明らかにして、次に**これを代替する方法はないか**を問い直す。
代替策を注入 (インジェクション) すれば、目標を達成するための必要条件は不要になる。

### コアの問題は雲と現状問題構造ツリーとつなげたもので伝える

相手に問題を説明して共有するには、雲から逆に現状問題構造ツリーとつなげる。

1. 雲を十分原因のツリーに転換する
	- 雲の先端の目標は十分原因ツリーのエントリーポイントになる
	- 雲の末端の必要条件 (代替策ではないほう) はコアの問題
2. 十分原因のツリーを現状問題構造ツリーに重ね合わせる
	- 雲の末端の必要条件を現状問題構造ツリーのコアの問題と重ねる
3. 重ね合わせたツリーを雲の目標 (エントリーポイント) から伝えていく
