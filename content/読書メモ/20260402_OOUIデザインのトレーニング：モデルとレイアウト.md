## いつ読むか？

- UI のレイアウト構成を検討するとき、どこから考えればいいか迷ったとき
- データモデルの関連が複雑で、画面構成の方針が決まらないとき
- 既存の UI 設計を見直して、モデルとレイアウトがずれていないか確認したいとき

## 読書メモ

モデルの構造がレイアウトパターンを決める、という一般則が整理されている。

| モデル | レイアウトの考え方 |
|---|---|
| 単一クラス | コレクション＋シングルの2画面 |
| 無関連の複数クラス | メインナビで切り替え |
| 自己参照クラス | 無限に続く前提で設計 |
| 関連ある複数クラス | メインオブジェクトを先に決める |
| 相互参照クラス | 複雑化しやすく複数ペインが困難 |

UI 設計時に「このモデルはどのパターンか？」を最初に問うことで、レイアウトの選択肢を絞り込める。
